# 小猫 · 引力场

一个在电脑浏览器运行的真实摄像头手势艺术作品。粉色粒子在流动的丝束轨道、立体字形与双层玻璃星花之间连续变化。33 条细光丝与粒子共用流场，手掌可以聚拢光、释放涟漪。完成数字倒数后，上排 I ♥ U 与下排「小猫」同时凝结，环绕爱心、十八片透明花瓣与星流烟花接续展开。所有变化保留用户随时张掌、切换和恢复的控制权。

Three.js / WebGL 2 负责画面；MediaPipe Hand Landmarker 在独立 Web Worker 中对摄像头逐帧推理。数字、英文、爱心与中文名字均由同一组粒子构成。

## 启动

需要 Node.js 20.19+ 或 22.12+（开发时使用 Node.js 24）。

```bash
cd pink-universe
npm ci
npm run dev
```

在同一台电脑的新版 Chrome、Edge 或 Safari 中打开 **http://127.0.0.1:5173/**（或 http://localhost:5173/）。点击「进入」，在浏览器中允许摄像头。不要直接双击 `index.html`。

`npm run dev` 和 `npm run build` 会自动准备本地 WASM 文件并构建兼容 MediaPipe 的 classic Worker。模型、完整中文字体、WASM 与程序均随项目提供；正常运行不需要请求 CDN 或外部 AI 服务。首次下载依赖需要网络，安装完成后可断网运行。

```bash
npm test         # 识别、流程锁、形变连续性、几何与摄像头生命周期测试
npm run build    # 生成完整静态网站到 dist/
npm run preview  # http://127.0.0.1:4173/ ，检查生产构建
```

部署时把 `dist/` 的全部内容放到静态主机，使用 **HTTPS**。远程 HTTP、`file://` 和普通局域网 HTTP 地址通常无法访问摄像头；localhost / 127.0.0.1 是本机例外。部署服务器需正确返回 `.wasm` 文件（`application/wasm`）；模型与字库不可遗漏。站点部署在子目录时使用 Vite 的 `--base` 配置，并保持资产路径一致。

## 怎么玩

一只手、掌心朝向镜头，距离约 40–80 cm，在明亮光线下短暂停稳。左右移动采用镜像坐标；预览也镜像一次，实时显示 21 个关节点及骨骼连线，跟随视频的等比裁切。

首次进入先依次比出 **3 → 2 → 1**。数字需由手势确认；倒数期间为换手势而握拳不会触发表白、消耗内容顺序或重置倒数。张掌只散开并保留当前进度，错序数字不会跳步。完成 1 后，新的一次握拳即可同时显示上排 I ♥ U 和下排「小猫」，并直接使用完整的花瓣与烟花动效，无需先张掌。此后每次确认张掌再握拳，都重新呈现同一组合；后续循环不再强制重做倒数。

| 手势 | 效果 |
| --- | --- |
| 五指自然张开 | 粒子展开为中空轨道光雕塑，泡泡漂浮；为下一次握拳解锁 |
| 食指伸直，其他手指收起 | 粒子数字 1 |
| 食指、中指伸直，其余收起 | 粒子数字 2 |
| 食指、中指、无名指伸直；拇指与小指弯曲相扣，指尖靠拢或轻触 | 粒子数字 3 |
| 完成 3 → 2 → 1 后第一次握拳 | 上排 I ♥ U、下排「小猫」同时由粒子凝结，环绕爱心、双层玻璃花瓣、分批心形与球形星流、上升泡泡接续展开 |
| 后续张开后再握拳 | 重新呈现同一双排组合与完整动效 |

手掌平稳停留约 3 秒，掌心附近会聚起细小光环与环绕光粒；再次移动，蓄积的光沿粒子、薄膜、花瓣和泡泡向外传播。缓慢移动轻轻牵引，快速划动留下旋转光迹。这些反馈只改变作品的光与运动，不推进内容，也不改变任何手势规则。丢手、恢复追踪或切换模式会取消未释放的蓄光。

表白之后，内部握拳顺序继续循环，三个阶段统一呈现同一双排作品。一直握拳只触发一次，只有确认张开手掌才解锁。插入数字、手离开镜头、无法确定的姿势都不消耗或重置顺序。切换演示或重启摄像头同样保留倒数进度与拳锁。

数字 3 **不使用**拇指、食指、中指的组合。分类器同时检查食指、中指、无名指伸直、小指弯曲，以及拇指向小指内收靠拢。正常使用三维关节信息；手掌正对镜头、相扣处有遮挡时，结合画面中可见的关节弯曲与接触位置判定，避免模型深度误差造成只有反手能识别。正反手、左右手使用相同的手指组合要求。

## 演示、设置与快捷键

开始画面仅显示「进入」。进入后仅保留角落的摄像头、帮助和设置图标；摄像头预览默认显示，可用小窗关闭按钮隐藏，隐藏预览不停止识别。

没有摄像头时，在简短的错误提示中选择「演示模式」；进入后也可在设置中切换。演示模式由角落的「演示」标记区分，不启用摄像头。移动鼠标控制粒子，主动打开手势帮助后可点击图示，或使用快捷键：

- `0`：张开 / 散开
- `3` → `2` → `1`：首次倒数；完成后可自由插入数字
- `Space`：握拳（首次倒数完成后呈现双排组合；之后需先按 `0` 才能再次触发）
- `F`：全屏；`H`：隐藏 / 显示界面；`Escape`：关闭弹层

右上角设置可分别更改下排名字（12 字内）、上排表白（36 字内）与细腻度，支持中文和英文，两排各自自动折行并缩放到画面内。设置只写入本机 `localStorage`。中文粒子使用完整的 **Noto Sans CJK SC Bold** 字库，包含 44,810 个 Unicode 映射，先确保字体加载成功再生成目标点。默认 I ♥ U 的爱心使用真实粒子几何。没有将 DOM 文字盖在粒子上冒充字形。

设置中可更改画质、切换摄像头与预览、进入演示、全屏或隐藏控件。声音默认关闭；开启后，氛围音和数字、场景切换的短音均由本机 Web Audio 合成，不下载音频文件。

模型只在真实模式工作；摄像头画面不被上传或持久化。关闭摄像头、切换演示、关闭页面及设备断开时释放摄像头。相机重启与模式切换保留握拳顺序和解锁状态。

进入前显示细光丝轨道、约三分之一的粒子与少量泡泡；进入后同一组粒子淡入完整密度，构图随窗口整体缩放。角落控件在停用后降低亮度，移动鼠标或聚焦时恢复。没有常驻标题、旁白、识别标签或底部控制栏。

## 性能与识别

- 主粒子按设备逻辑核心数使用 12,500 或 18,000 个；低画质使用 8,500 个均匀取样的粒子。泡泡为 22–40 个，惊喜烟花最多 2,400 个粒子。
- 轨道雕塑由交错螺旋与另一倾斜轨道面构成，保留中央留白。文字采用面与轮廓采样，分出前后发光面和侧缘；爱心具有鼓起的透镜表面与双重心跳。形变、细微漂浮、闪烁与镜像位移在 GPU 中完成。
- 空间舞台最多八次绘制，包含透明玫瑰薄膜、轨道刻线、地面焦散、悬浮光尘、扩散光环、光冠、玻璃花瓣和掌心涟漪，不使用贴图或全屏后处理。十八片花瓣合并为一次绘制，双层错峰展开；薄膜干涉色、边缘反光、细纹与手掌波动共同塑造厚度。文字区域保留留白。惊喜展开后再次张掌，轨道保留淡淡的花形记忆。
- 手部位置、速度与停留共同驱动局部吸引、回弹、光迹和泡泡偏移。四个可复用波纹槽连接粒子、丝束、花瓣和泡泡；不增加新手势。首次重新检测到手后有视觉反馈缓冲，防止跨画面恢复造成误释放。
- 倒数每完成一步，轨道中的蓄光弧增加一段。倒数后的第一次握拳即进入完整惊喜编排：上排表白与下排名字一同凝结，再用约 4 秒错峰打开两层花瓣，随后在外围释放分批心形与球形星流；留在场景中会再次出现星流。退出时花瓣、烟花和余光连续衰减，快速返回不会把尚未收拢的花瓣突然重置。释放后的波纹自然消退。
- 数字聚合 0.78 秒、散开 0.90 秒、双排组合聚合 1.38 秒，另有最多 0.10 秒粒子错峰。位移在前半段迅速完成主要汇流，再柔和收束；数字绕行幅度缩小，手的移动跟随更直接。
- 快速换手势时从当前粒子位置继续形变，CPU 位置快照与 GPU 使用一致的过渡公式，包含各场景不同的回旋路径。最多缓存 12 组字形目标，重复切换减少字体取样开销；GPU 属性与索引继续复用。上述时间为普通运动设置；系统开启「减少动态效果」时放慢动画。
- 自动模式观察实际帧率，必要时切换低画质，同时减少泡泡、烟花、光尘、光迹、光丝和像素比，保持所有文字完整；对窄屏的粒子覆盖率、低画质亮度做补偿，避免细字变暗。页面隐藏时暂停画面更新和声音。
- 模型在独立 classic Worker 中以 CPU WASM 运行。帧间隔根据推理耗时自适应，单帧在途限制避免请求堆积。
- 手部检测、存在与跟踪阈值均为 0.65；自定义几何质量阈值为 0.68。数字确认 120 ms、张掌 110 ms，且至少 3 次连续有效样本；握拳 170 ms 且至少 4 次，避免过渡拳误触。实际响应还受设备推理帧率影响。
- 短暂丢手维持当前作品，未知手势不触发切换；重新出现需重新积累证据。切回页面不会重置握拳内容顺序。

## 验证与已知边界

`npm test` 覆盖指定三指的接触容差、掌心朝前与深度偏差、拒绝错误拇食中组合、旋转/镜像/缩放、缺失数据、置信度与短时抖动、3 → 2 → 1 顺序、倒数握拳隔离、持续握拳锁、插入数字与循环顺序、骨骼镜像和宽屏/竖屏裁切、快速形变的端点与打断连续性、目标点确定性与有限边界、轨道留白与深度，以及摄像头授权、视频播放、模型初始化和帧捕获过程中的取消/重启竞态。

运行开发服务器后，访问 **http://127.0.0.1:5173/tests/model-check.html** 并点击检查按钮，可以用正式页面的同一个 Worker 运行真实模型，检查 Google MediaPipe 的公开手部照片（1、2、握拳、左右手张掌和旋转的 1），并显示中文粒子坐标结果。这是独立的开发检查页，不参与正式作品，也不会被打包进 `dist/`。

开发服务器还提供 **http://127.0.0.1:5173/tests/experience-check.html**：用公开照片生成 `canvas.captureStream(30)` 测试视频，仅在测试 iframe 中替换 `getUserMedia`，正式页面、真实模型 Worker、识别、确认和 UI 均保持原样。它检查默认预览、真实骨架绘制与丢手清空、倒数期间拳隔离、1/2 视频识别、完成 1 后直接握拳、持续握拳锁、隐藏预览继续识别、后续张掌解锁、相机重启保留顺序与锁、内部三阶段顺序、演示切换及循环。三个内部阶段均使用同一双排组合与完整动效。3 由正式演示帮助按钮确认，其指定手型另由几何测试覆盖，不冒充真实三指模型验证。测试结束释放视频流并恢复设置；此页面不会打包到正式作品。

本轮已通过 `npm test` 的 45 项测试与 `npm run build`。新增回归覆盖停留蓄光、单次释放、追踪恢复隔离、无效输入与固定波纹池。浏览器中的真实模型照片检查全部通过，正式应用视频流程检查为 **14 PASS / 0 FAIL**；并已检查横屏、390 × 844 竖屏及生产构建。

`tests/render-check.html` 另检查了 60 次连续中断转场、长中英文内容、五次画质切换、GPU 属性与索引复用。含光波与转场余光的惊喜为 13 次绘制、14 个几何资源；本次浏览器约 60.0 fps，超过 40 ms 的帧为 0，帧率只代表测试环境。新增浏览器检查还验证了光场到花瓣的联动、快速打断后继续展开和资源数量稳定。测试环境没有可用的实体摄像头，指定三指的真人实时识别仍需在目标电脑上试用；其掌心朝前、相扣指尖深度偏差、自然小指弯曲和正反手情况由几何回归测试覆盖。逆光、严重遮挡、手掌侧对镜头或极端弯曲可能降低识别稳定性。

## 代码

- `src/gestures.js`：21 点几何分类、姿态确认与镜像坐标
- `src/sequence.js`：首次倒数隔离、仅张掌解锁的后续握拳循环
- `src/hand-overlay.js`：实时骨骼与关节点、镜像裁切映射
- `src/tracker.js` / `src/tracking.worker.js`：摄像头生命周期和真实推理
- `src/shapes.js`：字库加载、离屏字形取样、轨道雕塑、立体爱心与双排组合目标
- `src/art.js`：同组粒子形变、虹彩泡泡、星尘、烟花、速度光迹和性能适配
- `src/spatial-stage.js`：透明薄膜、倒数蓄光、焦散、场景光环和掌心涟漪
- `src/bloom.js`：十八片双层玻璃花瓣、逐瓣展开、干涉色与波纹响应
- `src/flow-ribbons.js`：与主粒子共用的轨道流场、细光丝和爱心内部结构
- `src/interaction.js`：独立的停留蓄光、移动释放、追踪恢复缓冲和固定波纹池
- `src/motion.js`：快速形变时序、GPU 公式与连续位置采样
- `src/audio.js`：可选的本机合成氛围音与场景短音
- `src/main.js`：界面、设置、说明、错误、演示和键盘控制
- `scripts/prepare-assets.mjs`：本地运行库准备与 classic Worker 构建
